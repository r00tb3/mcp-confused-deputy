Suggested ticket update

Root cause

The MCP broker treats the tool schema as documentation rather than enforcement. fs.write declares path and content, but the dispatcher reads the entire arguments object, so an undeclared escalate: true reaches the privileged branch. The broker then acts with its own authority — reloading the config service — and attributes the side effect to the agent's write.

Why the agent never needed privilege

The agent only ever held a file scope. The deputy is the broker. It is the broker's privilege that was borrowed, which is why nothing in the agent's permissions looked wrong.

Fix

The elevation gate now runs ahead of path resolution and file I/O, so a rejected request produces no file write and no side effect. Verified: the identical payload returns -32002 and the service generation stays at 1.

Follow-up

A header check is a stopgap. It binds nothing to a session, a subject or a resource. Track replacing it with a session-bound capability token.
